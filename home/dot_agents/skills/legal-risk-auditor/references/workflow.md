**Load this reference when:** you are about to run a contract review and need the exact steps, their order, and the exit criterion of each step.

# 审查流程 - Review Workflow

本文档描述审查的五个步骤。步骤按顺序执行,后一步依赖前一步的产出。输入是 `.docx` 时,先完成 SKILL.md 的 **Step 0 转换与完整性校验**,再进入下面的 Step 1。

## Step 1 — 明确委托方立场

**动作**:确定本次审查代表哪一方:**甲方 / 乙方 / 中立**。同一条款在不同立场下严重程度会翻转——无限责任条款对甲方是可控敞口,对乙方是彻底的赔偿陷阱;单方解除权对甲方是便利,对乙方是高危。用户未说明时按「中立」处理并在报告中写明这一假设。

**退出标准**:报告表头「委托方立场」已填;该立场已代入每一条风险的评估,风险表中每一行都能看出立场如何影响结论。

## Step 2 — 提取当事人与关键事实

从合同中提取:

| 项目 | 内容 |
|:-----|:-----|
| 合同类型 | 买卖 / 租赁 / 服务(委托) / 劳动 / 借款 / 担保 / 技术 / 承揽 / 建设工程 / 运输 / 合伙 |
| 当事人 | 名称、身份(自然人 / 法人 / 非法人组织 / 个体工商户)、缔约资格、签约代表权限 |
| 标的 | 货物 / 服务 / 房屋 / 知识产权,数量与规格 |
| 权利义务 | 谁交付、谁付款、谁验收、谁承担风险 |
| 期限 | 生效、履行、验收、付款、质保、解除通知期限 |
| 违约后果 | 违约金、赔偿、解除、继续履行 |
| 争议解决 | 管辖法院或仲裁机构、适用法律、送达地址约定 |

**退出标准**:每个当事人、每个金额、每个期限都能在合同原文中找到出处;无法确认的事实记为「待确认」,不猜测。

## Step 3 — 锚定法条依据

把每个风险点对应到具体规范,并区分三类:

| 类别 | 违反后果 |
|:-----|:---------|
| 效力性强制性规定 | 条款或合同无效 |
| 管理性强制性规定 | 行政处罚,但不必然导致合同无效 |
| 任意性规定 | 可由当事人约定变更 |

**「待核实」兜底**:无法确认依据时,**不要猜法条号**。按下列格式记录,让后续能查证:

```
法条依据：待核实
待检索：具体条文（例：《民法典》合同编担保合同章关于保证期间的条款）
        或 司法解释名称 + 关键词（例：民间借贷司法解释 利率上限）
```

一条「待核实」的风险照样进入风险表并计分——依据待确认不等于风险不存在。

**退出标准**:每条风险要么有可指认的条文,要么是完整的「待核实 + 待检索项」。

## Step 4 — 风险评估与打分

按 **严重程度 × 发生概率** 打分;可修复性只作定性标注,不进入乘积。逐条产出:

风险等级(🔴/🟡/🔵) · 涉及条款 · 风险描述 · 法条依据(或「待核实」) · 举证责任 · 修改建议 · 可修复性 · 立场影响

**退出标准**:每条风险字段齐全;综合评分按 `max(0, min(100, 100 - Σ))` 计算;若存在 🔴 高危,已按严重度下限封顶并在报告中写明。

## Step 5 — 生成报告

按 `assets/review-report-template.md` 的五个章节输出,写到用户指定的路径。

**退出标准**:五章节齐全、表头含「委托方立场」与「法律状态核验日期」、末尾为免责声明原文。

## 风险标签与动作

| 标签 | 含义 | 动作 |
|:-----|:-----|:-----|
| 🔴 高危 | 合同无效或重大损失风险 | 必须修改 |
| 🟡 中危 | 履约争议风险 | 谈判 |
| 🔵 优化 | 精确度改进 | 建议 |
