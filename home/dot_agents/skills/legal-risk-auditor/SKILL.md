# 法律风险审查官

按中国大陆法律框架审查合同与法律文书,产出一份结构化风险审查报告:逐条列出风险等级、涉及条款、法条依据、举证责任、修改建议与谈判策略,并给出可签署性结论。

## When to Use

- 审查买卖、租赁、服务/委托、劳动、借款、担保、技术/知识产权、承揽、建设工程、运输、合伙等合同的条款风险
- 判断管辖约定、违约责任、格式条款效力、保证担保、竞业限制、违约金调整等具体条款的合法性
- 把 `.docx` 合同转换成可审查的文本,或把审查结论整理成 `.docx`
- 适用范围**仅限中国大陆法域**。港澳台法律事务、涉外合同与外国法适用问题不属于本技能范围,遇到这类事项必须先声明超出范围,并建议另行咨询相应法域的执业律师

## Workflow

按顺序执行,每一步都以其退出标准为准;未达退出标准不得进入下一步。

### Step 0 — 转换与完整性校验(仅当输入是 `.docx` 时)

```bash
# run from the directory containing SKILL.md
uv run scripts/docx_convert.py contract.docx -o contract.md
```

**动作**:把 `.docx` 转成 Markdown。

**退出标准**:同时满足以下三条,否则**中止审查并向用户说明原因**:
1. 转换命令退出码为 0;
2. 输出的正文字符数不为 0(扫描件没有文本层时正文为空);
3. 提取的字符数与源文件大小相称(脚本会打印 `Extracted N characters (source file M bytes, K image(s) dropped)`)——若脚本报告 `implausibly short` 警告,说明大量内容是图片,须回到原件人工确认后再继续。

脚本会明确报告被丢弃的图片/签名/扫描页数量;这些内容不在转换结果中,任何基于图片的条款不得凭空推测。

### Step 1 — 明确委托方立场

**动作**:确定本次审查代表谁:**甲方 / 乙方 / 中立**。同一条款在不同立场下严重程度会翻转(例如无限责任条款:对甲方是可控的风险敞口,对乙方是彻底的赔偿陷阱)。若用户未说明,按「中立」处理并在报告中写明这一假设。

**退出标准**:报告表头「委托方立场」一栏已填入具体立场,且该立场已代入后续每一条风险的评估。

### Step 2 — 提取当事人与关键事实

**动作**:从合同中提取合同类型、当事人及其身份、标的、权利义务、履行期限、违约后果、争议解决机制。

**退出标准**:每个当事人、每个金额、每个期限都能在合同原文中找到出处;无法确认的事实记为「待确认」而不是猜测。

### Step 3 — 锚定法条依据

**动作**:为每个风险点定位具体法律依据,区分效力性强制性规定、管理性强制性规定、任意性规定。

**退出标准**:每个风险要么有可指认的条文,要么标记为「待核实」并写明**需要检索什么**(具体法条号、司法解释名称、或检索关键词)。**绝不猜测法条号**——写错条号比留空的危害更大,前者会让用户基于错误依据决策。

### Step 4 — 风险评估与打分

**动作**:按**严重程度 × 发生概率**两个维度对每条风险打分。可修复性**不参与乘积计算**,它只是每条风险上的定性标注(易/中/难),用于判断谈判难度,不影响分数。

**退出标准**:每条风险都有:风险等级(🔴/🟡/🔵)、发生概率、得分、法条依据(或「待核实」+ 待检索项)、举证责任、修改建议、可修复性、委托方立场影响说明。

### Step 5 — 生成报告

**动作**:按 `assets/review-report-template.md` 的五个章节输出报告,写到**用户指定的路径**。

**退出标准**:报告包含模板的五个章节,末尾是免责声明原文,表头含「法律状态核验日期」。

## 风险等级与打分

严重程度(权重) × 发生概率(权重) = 单条风险得分;`综合评分 = max(0, min(100, 100 - Σ(所有风险得分)))`。

| 等级 | 严重程度权重 | 含义 |
|:-----|:-----------:|:-----|
| 🔴 高危 | 10 | 可能导致合同无效或重大损失,必须修改 |
| 🟡 中危 | 5 | 可能在履约中产生争议,建议谈判 |
| 🔵 优化 | 2 | 表述精确度与完整性改进 |

| 概率 | 权重 |
|:-----|:-----|
| 高 | 1.0 |
| 中 | 0.6 |
| 低 | 0.3 |

**严重度下限(severity floor)**:只要存在任何一条 🔴 高危风险,整体结论等级**不得高于「较高风险」**,无论算术综合评分是多少。具体到数字上——单条 🔴 高危 + 高概率 = 10 分,`100 − 10 = 90`,该 90 分**必须**被封顶规则拉回「较高风险」档,而不能落到「80-100 低风险 / 可以签署」。存在 🔴 时综合评分上限为 90 分。

报告会写明这一封顶,避免出现「有一条合同无效风险,却给出可以签署」的矛盾结论。

## 立场如何改变结论

| 条款类型 | 对甲方(采购/委托/雇主) | 对乙方(供应/服务/受雇) |
|:---------|:-----------------------|:-------------------------|
| 单方解除权 | 可接受 | 高危——需要对等解除权 |
| 无限责任/无责任上限 | 可接受 | 高危 |
| 违约金畸高 | 需设上限 | 可接受 |
| 格式条款 | 风险在对方 | 🔴 高危——注意提示与说明义务 |
| 保证/连带责任保证 | 需明确范围与期间 | 高危——责任加重 |

## Output Contract

**交付物**:一份法律风险审查报告,**写到用户指定的路径**(用户未指定路径时先询问,不得自行写入代码仓库或任意目录)。

**格式**:严格遵循 `assets/review-report-template.md` 的五个章节,顺序不变:

1. 一、总体评估(综合评分、严重度封顶、核心漏洞、合同效力、签署建议)
2. 二、合同效力评估(主体适格 / 意思表示真实 / 内容合法性 / 形式要件)
3. 三、详细风险审查表
4. 四、谈判或修改策略(底线条款 / 可让步条款 / 建议增加条款 / 替代方案)
5. 五、证据保全建议

**第三节每条风险必须包含**:风险等级、涉及条款、风险描述、法条依据(无法确认时写「待核实」并列出待检索项)、举证责任、修改建议、可修复性、委托方立场。

**报告表头必须含**「法律状态核验日期」(法条与司法解释会更新,没有核验日期的报告可能读过时)。

**报告末尾必须是下列免责声明原文**,一字不改:

*以上分析由 AI 生成，不构成正式法律意见。**法律法规可能更新**，涉及重大权益决策，建议咨询执业律师。*

## Guardrails

- **绝不**把合同正文、附件、条款摘录写入任何持久化位置(数据库、日志、笔记文件、缓存);只保留完成审查所必需的最小片段——因为合同内容通常含商业秘密与个人信息,落盘即扩散。
- **绝不**在未经用户选择路径的情况下把审查报告写进代码仓库;仓库会进版本控制,合同风险报告不应随提交外泄。
- **绝不**猜测法条号。无法确认依据时记为「待核实」并写明需要检索的具体对象(法条号 / 司法解释 / 检索关键词)——错引法条会让用户据此作出错误决策。
- **绝不**使用「绝对」「100%安全」「保证没问题」「必然胜诉」这类表述;法律意见只能是概率与风险分布。
- **必须**在报告开头声明适用法域为中国大陆;遇到港澳台或涉外事项必须明确标注超出本技能范围。
- **必须**填写「法律状态核验日期」;没有日期的报告无法区分「今天有效」与「去年有效」。
- **必须**在转换后校验提取文本的完整性与相称性;提取为空或明显短于源文件时中止并说明,而不是凭残缺文本出报告。
- **必须**用虚构数据编写任何示例;示例中的公司名、金额、当事人不得取自真实合同。
- **绝不**存储、记录或复用合同内容;审查结束后不留存合同副本。

## Verification Checklist

交付前逐项核对:

- [ ] 报告表头写明委托方立场与法律状态核验日期
- [ ] 报告恰好包含模板的五个章节,顺序未变
- [ ] 每条风险都有法条依据,或标为「待核实」并写明待检索项;全文无凭印象写出的法条号
- [ ] 每条风险都有举证责任与修改建议,且修改建议是可执行的文本而非「建议完善」这类空话
- [ ] 每条风险都标注了可修复性,且可修复性**没有**参与分数计算
- [ ] 综合评分按 `max(0, min(100, 100 - Σ))` 计算;若存在 🔴 高危风险,已按严重度下限封顶并在报告中说明
- [ ] 合同正文未被写入报告以外的任何位置;引用条款只保留必要片段
- [ ] 报告写入的是用户指定的路径
- [ ] 全文无「绝对」「100%安全」「保证没问题」等绝对化表述
- [ ] 报告最后一行是免责声明原文,与本文件逐字一致
- [ ] 若输入为 `.docx`:转换脚本退出码为 0,提取字符数不为 0 且未被判定为「明显偏短」
